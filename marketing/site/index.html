01 / The weekly cycle

Six stages. Software runs five. You run the one that moves money.

One command runs the lot on a schedule. Each stage leaves its own record, so a week that failed halfway is a week the report describes as failed halfway — never a week that quietly looks fine.

01Sync

Prices, FX, earnings dates and consensus, from a free feed.

main.py sync
02Triage

Rank holdings by what changed. Reserve capacity for anything overdue.

main.py triage
03Research

A deep pass on the selected few, against the thesis, with sources.

main.py research
04Recommend

Propose actions. Deterministic rules trim or refuse them.

main.py recommend
05 · youDecide

Approve, reject or snooze in Telegram. Approval reserves the cash.

/review
06Execute

You place the order in the app and record the real fill.

main.py executed

Findings stay separate from your thesis until you accept a revision. A model can propose a new version of why you hold something; it cannot overwrite the one you wrote.

02 / What it will not do

The rules are code. The model never sees them as a suggestion.

Every proposal passes through the same deterministic checks before anyone reads it. A brilliant argument for adding to your largest position gets the same answer as a bad one: no. The defaults below are sized for a portfolio of about EUR 1,400 across 14 names, where equal weight is 7%. Each one is an environment variable, documented where it is defined.

How recommendations are checked →

03 / Sourced, or labelled as background
A claim needs a citation Every finding cites a supplied evidence id and an exact excerpt.

Citations are checked mechanically: the id must exist in what the model was given and the quote must be verbatim. That establishes provenance, not truth — the report says so, every time.

Model memory is not news What the model knew from training is stored as background.

It cannot pose as a current fact. Research by default runs on recent news excerpts; you can add company releases and filings, linked to the questions they answer.

Unknowns are the output Each review ends with what would change your mind.

Unanswered questions are recorded on the thesis and carried forward. The habit being built is: what changed, what is still unknown, what evidence would settle it.

04 / A learning project, and the numbers say so

It will probably cost more than it earns. That is the deal.

On EUR 1,400, a weekly multi-model pipeline can spend more per year than any excess return it could find. The goal is a better research habit and an interesting system, not alpha. So the defaults are cheap, and every honest limit is printed rather than hidden.

  • 01Model output carries no investment authority. A model's "confidence: 91%" is not a calibrated probability, so it is never stored and never rendered as one.
  • 02Outcome evals are dead on arrival at this scale. Fourteen tickers a week will never tell one model's stock picking from another's, and replaying history leaks the future through the model's own weights. Evals measure process: schema validity, sourced claims, guardrails respected, stability across reruns.
  • 03The benchmark is recorded, never claimed. The same money in {{BENCHMARK_NAME}} is tracked forward from the seed date. It is the only comparison that will ever mean much, and it needs years before it means anything.
  • 04Cheap by default, expensive by choice. Each stage routes to its own model; the defaults reason on a budget tier and stronger models are opt-in and metered. Every call and its cost is logged.
  • 05Your holdings never enter the repository. The broker snapshot, the database, the context files and the Telegram ids live in your home directory. The repo ships invented example figures only.
05 / Get running in an evening

A screenshot of your broker is enough to start.

The book is seeded from a snapshot you write by hand: a quantity, a value and a blended return per position. Cost basis is derived from those, and init refuses to write if the derived total drifts from the broker's stated total. A mistyped figure cannot quietly become your cost basis.

What you need
  • Python 3.12+ and uv
  • A macOS or Linux machine for the scheduled run
  • A Telegram bot token and an LLM provider key
  • A broker that shows you quantity, value and return
# 1. Create your profile. --operator makes it the default.
$ uv run python main.py profile add adam --telegram-id 123456789 --operator

# 2. Describe your holdings. This file never leaves your machine.
$ cp seed_snapshot.example.toml ~/Documents/cash-ash/profiles/adam/seed_snapshot.toml

# 3. Check it reconciles against the broker's total, then seed.
$ uv run python main.py init --dry-run
$ uv run python main.py init

$ uv run python main.py sync           # prices and FX
$ uv run python main.py holdings       # positions, cost basis, P&L
$ uv run python main.py concentration  # weights, and what breaches
$ uv run python main.py doctor         # what is still missing

# Then write your thesis notes, and run the first week.
$ uv run python main.py thesis bootstrap
$ uv run python main.py weekly

Recommend. Approve. Execute by hand. Judge it later.
